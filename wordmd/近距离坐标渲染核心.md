# 近距离坐标渲染核心原理

## 问题背景

当传入的 x 和 y 坐标数组数值非常接近时，例如：

```javascript
x = [123.1234456, 123.345231, 123.45673213, 123.3421456]
y = [23.4563134, 23.4563456, 23.784565, 23.65345]
```

等值线图依然能够正确渲染，其核心原理在于 Plotly 的**坐标映射系统**和**基于索引的插值算法**。

---

## 核心原理一：分层坐标转换系统

Plotly 使用三层的坐标转换系统，将数据空间正确映射到屏幕像素空间：

### 1. 坐标转换链路

```
数据坐标 (c) ──→ 线性坐标 (l) ──→ 像素坐标 (p)
     c2l              l2p
```

对应的转换函数定义在 `src/plots/cartesian/set_convert.js`:

```javascript
// 线性到像素的转换（核心公式）
function _l2p(v, m, b) {
    return b + m * v;  // 像素 = 截距 + 斜率 × 线性值
}

// 像素到线性坐标的转换
function _p2l(px, m, b) {
    return (px - b) / m;  // 线性值 = (像素 - 截距) / 斜率
}

// 数据到线性坐标（log轴取对数，线性轴保持不变）
ax.c2l = (ax.type === 'log') ? toLog : ensureNumber;

// 数据到像素坐标
ax.c2p = (ax.type === 'log')
    ? function(v, clip) { return l2p(toLog(v, clip)); }
    : l2p;
```

### 2. 斜率与截距的计算

```javascript
// Y轴
ax._m = ax._length / (rl0 - rl1);  // 斜率 = 像素长度 / (范围上限 - 范围下限)
ax._b = -ax._m * rl1;              // 截距 = -斜率 × 范围下限

// X轴
ax._m = ax._length / (rl1 - rl0);  // 斜率 = 像素长度 / (范围上限 - 范围下限)
ax._b = -ax._m * rl0;              // 截距 = -斜率 × 范围下限
```

**关键点**：无论 x、y 值多么接近，系统会根据实际的数据范围（`rl0`, `rl1`）自动计算合适的斜率，确保数据正确映射到像素空间。

## 核心原理二：基于网格索引的插值算法

等值线的计算过程分为两步：先在**索引空间**插值，再转换到**像素空间**。

### 1. Marching Squares 算法

Marching Squares 算法工作在**网格索引空间**，而非直接使用 x、y 的实际值：

```javascript
// find_all_paths.js 中的 getInterpPx 函数
function getInterpPx(pi, loc, step) {
    var locx = loc[0] + Math.max(step[0], 0);  // 网格x索引
    var locy = loc[1] + Math.max(step[1], 0);  // 网格y索引
    var zxy = pi.z[locy][locx];                // 该位置的z值
    var xa = pi.xaxis;
    var ya = pi.yaxis;

    if(step[1]) {  // 在Y方向上插值
        // 计算插值比例（基于z值）
        var dx = (pi.level - zxy) / (pi.z[locy][locx + 1] - zxy);

        // 在线性空间插值（关键步骤）
        var dxl =
            (dx !== 1 ? (1 - dx) * xa.c2l(pi.x[locx]) : 0) +
            (dx !== 0 ? dx * xa.c2l(pi.x[locx + 1]) : 0);

        // 转换到像素坐标
        return [
            xa.c2p(xa.l2c(dxl), true),  // x像素坐标
            ya.c2p(pi.y[locy], true),   // y像素坐标
            locx + dx,                   // 插值后的x索引
            locy                         // y索引
        ];
    } else {  // 在X方向上插值
        var dy = (pi.level - zxy) / (pi.z[locy + 1][locx] - zxy);
        var dyl =
            (dy !== 1 ? (1 - dy) * ya.c2l(pi.y[locy]) : 0) +
            (dy !== 0 ? dy * ya.c2l(pi.y[locy + 1]) : 0);

        return [
            xa.c2p(pi.x[locx], true),
            ya.c2p(ya.l2c(dyl), true),
            locx,
            locy + dy
        ];
    }
}
```

### 2. 为什么坐标接近也能正确渲染

1. **索引无关性**：算法首先基于网格索引 `locx`, `locy` 工作，不关心实际坐标值的大小

2. **线性插值**：在计算出等值线穿过网格单元的位置后，使用线性插值：
   ```
   dxl = (1 - dx) × c2l(x[i]) + dx × c2l(x[i+1])
   ```
   这里 `c2l` 可能是对数转换（log轴）或恒等转换（线性轴）

3. **最终映射**：插值结果通过 `c2p` 函数映射到像素空间，这个函数会根据坐标轴的实际范围自动调整

## 核心原理三：示例推演

假设输入：
```javascript
x = [123.123, 123.345, 123.456, 123.234]  // 范围约 0.333
y = [23.456, 23.456, 23.784, 23.653]      // 范围约 0.328
```

### 步骤 1：确定坐标轴范围

```javascript
x轴范围: [123.123, 123.456]
y轴范围: [23.456, 23.784]
```

### 步骤 2：计算线性转换参数

假设画布宽度 800px，高度 600px：

```javascript
// X轴
ax._length = 800
ax._m = 800 / (123.456 - 123.123) = 800 / 0.333 ≈ 2402
ax._b = -2402 × 123.123 ≈ -295,779

// Y轴
ax._length = 600
ax._m = 600 / (23.784 - 23.456) = 600 / 0.328 ≈ 1829
ax._b = -1829 × 23.456 ≈ -42,898
```

### 步骤 3：坐标转换示例

将 x = 123.345 转换为像素坐标：

```javascript
// 线性坐标（linear轴直接使用原值）
l = c2l(123.345) = 123.345

// 像素坐标
px = _l2p(123.345, 2402, -295779)
px = -295779 + 2402 × 123.345
px ≈ 400.5  (画布中间位置)
```

**结论**：即使 x 值的变化只有 0.333，通过斜率放大（×2402），在像素空间得到了合理的分布。

## 核心原理四：非均匀网格支持

Plotly 的实现天然支持非均匀的 x、y 数组：

```javascript
// 每个网格单元使用其实际坐标值进行插值
var dxl = (1 - dx) * xa.c2l(pi.x[locx]) + dx * xa.c2l(pi.x[locx + 1]);
```

这意味着：
- x 或 y 数组可以是非等间距的
- 每个网格单元的物理尺寸可以不同
- 插值会在每个单元内根据其实际边界值计算

## 总结

近距离坐标能正确渲染等值线的根本原因：

1. **相对范围映射**：坐标系统根据数据的最小值和最大值自动计算映射参数
2. **索引空间计算**：等值线算法在网格索引空间工作，与绝对坐标值无关
3. **最终统一映射**：所有点在最后阶段通过相同的 `c2p` 函数映射到像素空间
4. **浮点精度保持**：使用双精度浮点数，即使坐标差异很小也能保持足够精度

这种设计使得算法既能处理 `[0, 1]` 范围的数据，也能处理 `[123.123, 123.456]` 这样接近的坐标值。
